# 宣传预设与视频制作逻辑

更新：2026-10-14。适用于当前 free-video-gen 本地工作台中的环境展示与通用服务／产品展示；足浴监控、专属按摩护理、短剧和复刻继续使用各自工作流。

## 用户流程

第一次：填写宣传资料 → 保存宣传预设 → 选择表现模板与数量 → 生成一条样片 → 同页看视频 → 满意后生成剩余视频。

以后：选择已保存预设 → 选择表现模板 → 生成样片 → 看视频 → 生成剩余视频。

选择豆包账号池时，环境与服务展示直接用宣传资料和已选模板在本机组织视频描述，不调用 TokenDance 文本接口。其他服务仍可使用已配置的文本模型优化描述。

提示词是内部制作材料。默认页面不展示提示词数量、下载提示词或要求确认提示词。只有成片的“查看生成详情与提示词”入口提供排查与修订。后台准备内容后自动提交视频，关闭页面不会阻断这次提交；重新打开页面能继续查看进度。

## 宣传预设保存什么

| 资料 | 用途 | 填写规则 |
| --- | --- | --- |
| 宣传主体名称 | 确定店铺、产品或服务身份 | 必填 |
| 已确认卖点 | 决定视频需要证明什么 | 必填，事实优先，避免堆叠形容词 |
| 宣传文字 | 保留用户需要说的话 | 选填，留空时从卖点自动组织 |
| 环境图 | 固定门店与真实空间 | 环境展示必填；服务展示可以使用服务场景图 |
| 产品／服务图 | 固定产品外观、工具与服务动作资料 | 产品外观图、过程照片都可 |
| 人物图 | 固定讲解者或服务者身份 | 人物模板可上传，也可填写人物身份与形象 |
| 服务／使用步骤 | 说明谁对什么对象做什么 | 过程类优先加工一个关键步骤 |
| 受众与行动 | 决定话术和收尾 | 选填，例如附近上班族、预约体验 |
| 人物职责与声音 | 明确讲解者、工作人员和顾客 | 人物图不当作环境背景 |
| 活动开始／结束日期 | 活动宣传文案 | 选填，结束不早于开始；不作为监控时间戳 |

用户口述中的“日期的起始”尚未明确，因此当前只提供可选活动日期，不实现定时发布或其他日期机制。

预设独立于项目，保存资料快照；当前项目修改不会回写旧预设。同一行业的一份资料可分别创建环境展示项目和服务展示项目。图片保存为本地素材引用，素材缺失时要求补充，不用文件名推测事实。

## 固定 case 的素材位置

固定的是资料角色与叙事位置，不要求用户填写提示词变量：

- 环境槽：只提供空间、装修、门窗与可见设施。
- 产品／服务槽：提供产品外观、工具、服务过程证据。
- 人物槽：提供同一人物身份与造型。
- 卖点槽：位于画面证明与讲解的核心位置。
- 宣传文案槽：提供可精简但不更改事实的台词。
- 收尾槽：提供预约、到店或了解详情的行动。

提交多图任务时按真实附件顺序追加角色说明，避免把人物肖像当背景或把产品照片当场景。直接使用首帧时只发送该起始画面，界面明确提醒其他角色需要已包含在画面中。文字、标志、电话号码等不能仅靠视频提示词保证逐字正确；当前没有自动品牌图层合成。

## 两类展示的表现模板

| 环境展示 | 核心画面 | 重点 |
| --- | --- | --- |
| 空间全景 | 平稳推进或小幅平移 | 看清真实空间和一处主要设施 |
| 设施细节 | 近景、小幅运动 | 材质与设施的真实用途 |
| 人物带逛 | 同一人物自然指示 | 人物是导览线索，环境是主角 |
| 第一视角体验 | 人眼高度观察 | 让观众想象自己到店 |
| 问答看环境 | 一个问题、一个回答 | 回答与画面证据对应 |

| 服务展示 | 核心画面 | 重点 |
| --- | --- | --- |
| 人物介绍 | 工作人员自然讲解 | 提供什么、适合谁，不强制持商品 |
| 过程展示 | 一个关键操作步骤 | 执行者、对象、工具与接触位置 |
| 顾客问答 | 顾客提问、人员回答 | 用事实回答一个顾虑 |
| 跟随体验 | 服务旅程的一段 | 真实步骤自然承接 |
| 卖点实证 | 操作或可见细节 | 用画面证明卖点，不杜撰体验结果 |

每个选中的模板按自己的数量生成独立短视频，构成一套作品。本次没有把多条视频自动剪成一条长广告，也没有实现跨任务的一镜到底。

## 内部编写规则

环境展示重点回答“这里是什么样、有什么值得来”；服务展示回答“提供什么、怎么完成、为什么对我有用”。模板先选择一个主要信息，再安排吸引注意、画面证明和简洁收尾。5秒镜头不塞入完整服务旅程，口播或问答不能超过可自然说完的长度。

参考图片负责外观与构图；视频描述优先处理主体动作、镜头运动、节奏与声音。环境类允许模板规定的自然运镜，不套用固定监控画质；服务类不套用家庭按摩、年轻女性随机换装或暧昧互动。人物身份、商品包装、颜色、环境结构沿用真实素材。

卖点、价格、功效、资质、客户评价等只取用户提供的事实。没有实测资料时不生成前后对比或顾客证言。人物口播、双人对话需要支持声音的服务；能力不匹配时明确阻止提交。

## 后台制作与样片确认

1. 点击“生成一条样片”，只准备所选模板的一条描述并提交一条视频。
2. 准备失败显示原因，不停在等待用户点击“生成视频”的中间阶段。
3. 视频完成且取得成片地址，才显示可验收的样片。
4. “满意，生成剩余 N 条”确认有效样片，仅补剩余槽位，已通过样片不重做。
5. 修改宣传资料、底图、模板或关键参数后，旧样片无法用于相应批量确认。
6. 重复点击和重复请求不重复生产；已批量提交的项目通过单项重试恢复。
7. 未知上游提交结果保留核对状态，不自动重复提交。
8. 后台重启中断准备时显示可重试失败；已经排队的视频沿用既有队列恢复。

## 资料依据与本项目的设计判断

以下为公开的一手资料。资料提供广告与模型的通用原则；“五种环境模板、五种服务模板、宣传预设与样片确认流程”是结合本项目需求设计的实现方案，并非资料对成片质量的保证。

- [TikTok 官方叙事工作表](https://ads.tiktok.com/business/library/Storytelling_Formats_One_Pager_SMB.pdf)：将宣传组织为开头、中段、收尾，并在制作前明确问题、利益与观众行动。
- [TikTok 官方专业服务指南](https://ads.tiktok.com/business/en/guides/professional-services-marketing-guide)：服务宣传需要展示专业过程和可信信息，不能只做漂亮画面。
- [TikTok 官方旅游宣传指南](https://ads.tiktok.com/business/en/guides/travel-and-advertising-guide)：环境类内容可以通过真实体验让观众想象自己置身其中。
- [Runway 官方图生视频指南](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)：输入图提供外观与构图，描述重点放在运动与时间推进。
- [Runway 官方参考素材指南](https://help.runwayml.com/hc/en-us/articles/52963720640275-Using-reference-media-to-guide-your-generations)：可命名保存参考素材供以后重复使用，并明确素材引用。
- [ByteDance Seedance 2.0 官方介绍](https://seed.bytedance.com/en/seedance2_0)：多模态参考和音视频生成能力；具体可用参数以当前接入的服务为准，不能把官网全部能力等同于豆包账号池或其他适配器能力。

## 验证范围

新增后台回归覆盖：只生成样片、自动提交、剩余槽位抵扣、重复请求、旧样片失效、失败与重启恢复、预设复用、单槽描述修订。浏览器检查使用拦截接口，覆盖表单、模板选择、保存预设、连续制作状态、同页结果、播放器保留及窄屏布局。

这些检查没有调用真实生成服务。实际视频的镜头稳定性、人物一致性、对白、空间真实性和宣传效果仍需用真实样片验收。
