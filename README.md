# 帧间 · 图生视频工作台

本地批量图片与视频工作台。当前主流程是：生成提示词 → 人工审核 → 批量图片 → 逐图补充视频指令 → 自由参考生成视频。

## 双模式主界面

根页面现在提供两条可选流程：

1. **足浴店底图 → 多个视频**：固定一张足浴店走廊/房门背景，从 14 套开门、关门、走廊动作模板中手动选择或随机组合，人物外貌与穿搭按批次变化，先试片再批量。
2. **每张家庭按摩参考图 → 一个不同视频**：每条图片只作为人物、穿搭、品牌和家庭氛围参考，不作为固定首帧；系统为每条任务分配不同镜头、朝向、动作节奏和随机种子。

家庭按摩模式位于 `/?mode=paired`；足浴店 14 动作模板模式位于 `/?mode=store`。两个页面顶部都保留模式切换；旧 `/legacy` 地址会转到足浴店模板模式。

足浴店底图库与家庭按摩生成图完全隔离：只有用户主动上传的足浴店底图及其“老旧监控底图”加工结果会出现在模式一；每张底图右上角都提供删除按钮。

## 自由参考视频

- Wan 3.0 路由使用原生 `reference_image`，不会把图片锁定为 `first_frame`。
- APIMart 与豆包在当前适配器未明确支持自由参考图时，使用图片提示词形成的视觉描述重绘，不会暗中提交首帧模式。
- 每张图片都有独立“视频补充”输入框；整批要求也可一键填入每条。
- 每条最终视频提示词固定加入“配上优雅暧昧的音乐”，并约束为无歌词纯音乐、无对白和无可听见人声；界面会在提示词预览与视频任务卡上明确显示。
- 视频完成后可直接下载单条 MP4；批次结束后可点击“一键下载全部”先保存到本机缓存，再自动下载 ZIP。
- 人工补充拥有最高动作优先级。例如输入“人物背过去，改为按摩背部，从后侧拍”，会覆盖默认足部按摩动作，但保留人物安全、品牌和家庭场景约束。
- 同一批图片可以反复生成新的视频版本，不需要重新生图。

关键模块：

- `video-directions.js`：镜头、动态变化和人工指令优先级。
- `paired-batches.js`：参考图绑定方式与一图一任务约束。
- `keyframe-batches.js`：图片审核、逐条视频指令和多版本视频批次。
- `wan.js`：`reference_image` 与 `first_frame` 的真实 API 映射。

## 内容模板扩展

两个大模式已经抽象为执行引擎：`background-variants` 与 `reference-pairs`。足浴店、家庭按摩、KTV 大厅或足浴店大厅等具体业务改为 `content-packs/*/pack.json` 内容模板，不再复制页面。`GET /api/content-packs` 会列出当前登记模板，页面导航会自动为 `active` 内容包生成按钮。

KTV 内容包当前包含 12 套锁定动作，覆盖包厢唱歌、合唱、碰杯、倒饮料、桌边游戏、点歌、欢呼、聊天、大厅迎宾、前台核对、走廊带路和轻舞。人物全部为成年人，女性限定 22–30 岁，服装可以鲜艳但必须常规领、不透明且完整遮挡胸线。

`/story` 提供 15 秒短剧广告：输入甲方名称和真实宣传资料，选择生活模拟、KTV 或监控视角，大模型批量生成两人争执与广告反转提示词；人工确认后，提交到支持 15 秒的文生视频路由。

参考视频创建新模板、15 秒多镜头成片和两人对话短剧的完整设计见 [`docs/CONTENT_PACK_ARCHITECTURE.md`](docs/CONTENT_PACK_ARCHITECTURE.md)。

“伊趣舒心”首帧模板固定以下规则：

- 场景只能是普通家庭客厅沙发或普通家庭卧室床上。
- 人物脸型、发型、身材和日常得体穿搭由提示词大模型生成；服务端校验批内人物外貌描述唯一，重复时拒绝进入生图。
- 允许脚部完整出现、局部出现或不直接露出；人像重点构图仍需通过姿态让人理解是足部按摩。
- 画面重点只有“技师形象”和“按摩动作”；按摩动作构图也必须完整带到技师面部或上半身，不提供“重点展示家庭环境”。
- 不穿工服或制服；独立胸牌准确显示“伊趣舒心”。
- 常规圆领或高圆领，胸线完整遮挡；禁止低胸、深 V、乳沟、透视或夸张开衩。
- 禁止浴巾、专业脚凳、足浴椅、足浴会所、酒店和按摩店装修。

相关接口：

- `POST /api/pair-plans`：只规划多样化首帧/视频提示词，不调用模型。
- `POST /api/keyframe-prompt-batches`：调用提示词大模型生成整批唯一人物与穿搭提示词，返回前执行重复和服装约束校验。
- `POST /api/keyframe-batches`：确认参数和数量后创建首帧图片批次。
- `GET /api/keyframe-batches/:id`：刷新生图状态并保存完成图片。
- `POST /api/keyframe-batches/:id/regenerate`：重生成审核不通过的单张图片。
- `POST /api/keyframe-batches/:id/confirm`：将勾选图片、整批补充和逐条补充送入新的视频版本队列。

## Windows 安装与启动

1. 安装 Node.js 24 或更新版本。
2. 首次使用时在项目目录运行 `npm install`。
3. 运行 `pwsh -File setup-key.ps1` 保存 API 密钥。APIMart 必填，TokenDance 与阿里云百炼可按实际使用的 Wan3 路由选填。密钥通过 Windows DPAPI 加密，不写入项目源码。
4. 双击 `启动工作台.cmd`，或运行 `npm run desktop`。

浏览器模式可运行 `npm start`，但独立豆包账号会话只在 Electron 桌面端可用。

把项目交给另一台电脑上的开发 Agent 时，直接附上 `AGENT_MIGRATION.md`。该文档包含完整 API 路由、缺失数据、加密密钥录入和验收步骤。

## 固定底图流程

1. 上传 JPG、PNG、WebP 或 GIF 底图，最大 20MB。
2. 图像模型建立场景档案：空间类型、固定视角、可行走区域、真实房门、出入口、透视、最多人物数和场景标签。
3. 14 个动作模板按底图条件显示兼容状态。不兼容模板会说明缺少真实房门、刷卡门、近处房门、连续通道、三人侧区或人物容量。
4. 手动选择一个模板，或从兼容集合随机选择。一次视频始终只使用一个模板 ID。
5. Qwen 仅生成人物外貌与穿搭。男性只使用日常休闲装；女性服装在得体的修身服装池中轮换。随机模式会拒绝同批完全重复组合。
6. 程序拼接底图描述、人物穿搭、锁定动作原文、固定结束状态、老旧摄像头画质和无歌词纯音乐规则。
7. 先生成一条试片，确认后再生成剩余视频。

普通照片也可以先点击“加工为老旧监控底图”。系统调用 APIMart 生图模型，在严格保留原场景内容的前提下调整为高位 45 度俯拍、老式广角镜头、灰蒙低对比、轻微模糊、噪点和压缩痕迹，并为每张图生成不同的时间戳。生成结果会保存成新的底图并重新建立场景档案。

## 视频模型与参数

页面提供一组简化参数：视频模型、API 额度来源、时间、底图、数量、提示词补充和分辨率。分辨率默认 `480P`。

- `wan3.0-video / TokenDance`：异步提交后轮询 TokenDance 任务接口。
- `wan3.0-video / 阿里云百炼`：异步提交后轮询阿里云任务接口。
- `Grok Video / APIMart`：保留现有 APIMart 路由。
- `豆包 Seedance / 豆包账号池`：提示词开头会明确写入所选视频时长，再交给本机账号池。

Wan3 在“自由参考”流程使用 `reference_image`；仅固定图片试片流程使用 `first_frame`。提交接口没有幂等键，因此创建请求网络超时后不会自动重试，避免重复创建和计费。远端返回的视频签名地址需要及时下载到本地缓存。

图像模型分析失败或识别不准确时，可在页面点击“人工校正”，只填写底图中真实存在的空间条件。

## 14 个动作模板

模板源文件位于 `prompt-skills/foot-spa-video-prompt-skill/actions/`。服务启动时动态读取 Markdown frontmatter 与“固定动作正文”，并强制校验 14 个稳定且唯一的 ID。动作文本不会交给 Qwen 重写。

接口：

- `GET /api/actions?referenceId=...`：动作与兼容性。
- `POST /api/references`：上传底图。
- `POST /api/references/:id/analyze`：模型分析；请求体带 `sceneProfile` 时保存人工校正。
- `POST /api/references/:id/prompt-preview`：预览分段提示词。
- `POST /api/trials`：创建试片和批次计划。
- `POST /api/image-transforms`：提交普通照片的监控底图加工任务。
- `GET /api/image-transforms/:id`：刷新生图任务并在成功后自动保存、分析新底图。

## 豆包账号池

豆包账号页在 Electron 工作台内容纳多个相互隔离的本地登录会话，再同步给内置 DoubaoManager 执行：

- 启动工作台时会自动检查并启动内置 DoubaoManager 后台服务；关闭工作台时同步退出。
- 首次启动若组件不存在，会自动下载源码、建立 Python 环境并安装 Playwright Chromium，后续启动直接复用。
- “新增本地账号”只在工作台右侧打开豆包，不会弹出 Chrome for Testing。
- 每个账号使用独立持久化会话；登录后点击“同步”，才会加入后台执行池。
- 账号的启用、停用、删除、今日额度均来自 DoubaoManager。
- 提交 N 个豆包任务时会按可用账号数自动调整并发（上限 10），并优先为每个未完成任务保留不同账号。
- Seedance 时长只允许上游真实支持的 5 秒或 10 秒；分辨率由豆包决定。
- 多条任务轮询共享短时任务快照，避免每条任务重复拉取整张远端任务表。

工作台仍通过 `doubao.js` 对本机 DoubaoManager API 提交、轮询并获取结果地址。正式生产前仍需在 Windows 上使用真实账号做端到端验收，因为豆包网页协议改版后可能需要更新 DoubaoManager。

内置服务默认监听 `127.0.0.1:4213`，可通过 `DOUBAO_MANAGER_PORT` 修改。运行日志保存在 `data/doubao-manager.log`。`安装并启动豆包管理器.cmd` 仅作为兼容入口保留，现在会直接启动完整工作台，不再要求用户分别运行两个程序。

## 画质与声音固定规则

每条提示词固定包含老旧摄像头拍摄、固定高位视角、轻微模糊、灰蒙雾感、低对比、噪点、视频压缩痕迹，并保留底图已有时间戳与通道编号。提示词不会写 `CCTV`。音轨只有优雅、舒缓、无歌词的纯音乐；人物可以有嘴型，不能有可听见的人声、对白或耳语。

## 网络与视频下载

首次试览通过 `/api/video/:id?preview=1` 按需转发 HTTP Range，不再等待整条下载；关闭或切换视频会释放上游流。已有本机缓存优先本地播放，支持前后拖动与尾部范围请求。点击“保存到本机”仍走断点续传和串行下载，默认每秒 128 KiB；实时预览按视频源可用带宽加载，不受归档下载限速约束，仍可能经过系统 VPN/TUN。网络较差时可保存完成后重新打开，使用本机播放。

实现依据：[MDN HTTP Range requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests)。MP4 元数据位于文件末尾时，播放器可通过尾部 Range 读取；源不支持 Range 时仍受源响应限制。[FFmpeg 文档](https://ffmpeg.org/ffmpeg-formats.html) 也说明 `+faststart` 可将 MP4 元数据移到文件开头，作为上游导出优化；本项目当前不自动转码。

## 验证

运行 `npm test`。测试覆盖：14 个模板 ID、空间兼容筛选、动作原文与结束状态锁定、固定画质与声音、禁用 `CCTV` 字样、随机只选兼容模板、Wan3 请求与状态映射、监控底图时间戳，以及现有视频缓存和下载限流。

## 多模板提示词工作流

足浴店与 KTV 的动作模板支持多选。右侧为每个选中模板显示名称、时长、数量和一个选填想法输入框。默认 5 秒，每次最多 15 秒，实际可选时长按视频模型能力收窄；短剧保留原时长规格。确认模板即切换到提示词生成页，每个模板按自己数量分别调用大模型。结果按模板折叠分组，画面摘要显示时长，全文可在弹窗编辑并自动保存。勾选后确认生成，只提交所选画面，各画面的时长与想法保留。模板设置及多选名单可保存为预设。

“生成历史”默认显示全部门店批次（含收纳记录），按日期展开，可搜索和继续查看；“全部内容 · 提示词与视频”打开所有内容的归档库，包括家庭按摩、短剧、复刻和提示词记录。

## 历史封面与动作示例

生成历史用真实视频首帧作为封面，点击播放或展开整批视频，支持状态、日期和收纳筛选。查看历史时隐藏右侧生成参数，扩大预览区域。封面仅在进入可见区域时加载，并发上限两条，抓取首帧后释放视频连接；JPEG 本机缓存保存在 data/video-presentation。全内容归档库也显示视频封面。

足浴店和 KTV 的每个动作模板有示例区。默认从同内容包、同动作的已完成视频选取，失败任务不作为示例；可在“更换示例”中指定历史成片，或上传最多 50 MB 的本地 MP4。没有对应成片的模板显示“添加示例”。示例映射可重启恢复，旧上传文件保留，播放示例不会改变模板选择。示例作为观看参考，不自动作为生成模型的附件。

复刻分析模型输出须满足占位符与相对时间规则。模型结果结构校验失败时携带具体错误与前一次结果进行修正，总共最多三次分析调用；网络错误立即退出。页面保留参考记录，并显示分析阶段及失败后重试说明。
