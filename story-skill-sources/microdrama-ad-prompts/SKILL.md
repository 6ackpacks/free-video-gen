# 30秒微短剧带货提示词生成工作流

默认按阶段推进，不要直接生成完整提示词。默认并优先生成30秒；用户未说明时长时直接按30秒执行，不追问时长，不自动扩展为60秒。第1步信息完整后不单独等待确认。

## 第1步：产品信息与卖点

首次启动且用户尚未提供产品信息时，用自然口吻引导：

> 好的，让我们从你的产品开始吧。先告诉我品牌和产品名称，以及最想突出的卖点；如果已经想好目标人群，也可以一起告诉我。缺少的信息，我会陪你一步步补齐。
>
> 比如：韩束面霜，主打抗衰，想卖给经常熬夜的年轻女性。

用户已经提供部分信息时，不重复欢迎语。只有品牌或产品名称无法识别时才补问；卖点或目标人群未提供时不追问，不阻塞流程。

优先记录以下信息：

- 品牌名称
- 产品名称或品类
- 1至2个核心卖点，可选

可同时记录使用场景、题材偏好、固定口播、必须出现内容和禁止内容。产品图只能用于识别可见的瓶型、颜色、包装和标识，不猜测成分、容量或功效。

本步不提供题材建议。

品牌名称和产品名称或品类明确时，先简洁复述已收到的信息，并在同一轮直接执行第2步，不询问“是否确认”，不等待用户回复“确认”。卖点未提供时，使用该品类常见使用场景或消费需求作为暂定创作方向，不把推断写成具体功效、成分或效果承诺，也不向用户追问。

## 第2步：短剧题材建议

完整读取 [topics.md](references/topics.md)，按照其中的22个题材大类、产品匹配和输出规则展示题材菜单，并结合产品、卖点和人群推荐不超过3个题材。本步不读取爆款剧情原型库，不提前设计剧情。

每个推荐只说明该题材为什么适合产品卖点和目标人群。

用户可回复：
```text
按推荐
3
换一批
自定义：仙侠复仇
```
用户回复题材编号、题材名称或“按推荐”时，即视为完成第2步确认，直接进入第3步，不复述推荐理由，不再次请求确认。“按推荐”默认选择排在第一位的优先推荐。只有用户表达犹豫、询问区别或要求换一批时，才停留在第2步。

## 第3步：核心创意

完整读取 [story-ideas.md](references/story-ideas.md) 的改编规则、产品作用说明和已确认题材的同名章节，从中选择3个不同的爆款剧情原型，分别结合已确认产品生成3个核心创意方向。

每个方向必须保留所选原型的三个戏剧锚点：开场异常或冲突、冲突升级的核心机制、结尾反转方向。允许根据产品重构中间事件、人物动机和揭晓方式，不必照搬原型的事件数量、逐项顺序、具体动作或证物形态，但不得破坏三个锚点之间的因果关系。

每个方向至少改编人物关系、行动目标、发生场景、冲突载体、升级方式、证据或秘密、产品作用、最终行动中的3项，避免只给原型换皮。不得新增无关主线、无铺垫的终极反转或突然出现的救场人物；不得复制具体作品的角色名、原台词、片名或独特世界观。

每个方向的一句话必须包括：
```text
题材与人物关系 + 主角想要达成的目标
+ 突然出现的冲突或危机 + 冲突升级方式
+ 出人意料的转折 + 产品在结局中的关键作用
+ 带货收口
```

上述公式用于检查改编后是否讲清完整逻辑。产品不能只是被拿出来使用，应优先承担原型建议的关键证物、破局工具、关系证物、身份线索或状态触发作用；确有更自然的方式时可以调整，但必须真实参与转折、证明或人物选择。

节奏要求：前20秒快速抛出异常事件，建立人物目标，让冲突连续升级并制造悬念；后10秒揭晓关键信息，让产品推动反转、解决核心冲突，并自然完成卖点表达和转化动作。

固定输出3个编号方向。每个方向先写一个不超过6个中文字符的创意名，再写一个200字以内的完整中文句子，以讲清爆款原型如何完成产品化改编为准。本步不展示原型名称、改编规则、来源或锚点分析，不展开台词、运镜、光影和画质，不编造功效、价格或促销信息。

输出后用自然口吻邀请用户选择或修改，不使用表单式命令。默认可写：

> 你更喜欢哪个方向？哪里还不够对味，也可以直接告诉我，我再按你的想法调整。

用户回复1、2、3或创意名时，即视为确认该核心创意，直接进入第4步，不再次请求确认；用户提出建议或要求修改某个方向时，只重做受影响方向。

## 第4步：导演时间轴

根据已确认的核心创意，在内部补全人物关系、人物设定、核心冲突、产品功能、反转路径、包装适配和固定收尾口播，不单独列出这些字段。

完整读取 [prompt-rules.md](references/prompt-rules.md)，严格按照其中的“六段节奏”和“整体视听与一致性”生成6段、每段5秒的导演时间轴，不改写或简化其中的硬性规则。

在内部保持人物、场景和产品前后一致，不单独输出连续性说明。将6段导演时间轴直接交给用户确认；确认前不要输出最终提示词。结尾用自然口吻请用户检查剧情，默认可写：

> 你先看看这版剧情顺不顺、有没有想改的地方。要是没问题，我就接着把它整理成可直接用于文生视频的完整提示词，音乐、对白、运镜和音效都会一起写进去。

## 第5步：最终提示词

仅在第4步确认后执行。重新完整读取 [prompt-rules.md](references/prompt-rules.md)，按照其中的固定模块顺序、负面提示词和最终模板，忠实编译第4步已确认内容，不新增剧情信息。最终提示词必须完整包含画面内容、人物动作、人物对白、运镜与转场、环境音效、背景音乐、光影风格和产品植入。

先在内部判断剧情是否带货：包含产品使用、品牌揭晓或转化动作即为带货。带货时启用植入和产品模块；非带货时省略这些模块，不解释判断过程。

最终只输出提示词本身，不添加前言、说明、备注、核对结果或采用假设。不得更改固定模块名称、顺序和标点。

## 交互原则

1. 用户只提供品牌、产品、卖点或目标人群中的部分信息也能启动。
2. 只有品牌或产品名称无法识别时才补问；不因缺少卖点或目标人群反复追问。
3. 第1步的品牌名称、产品名称或品类已经明确时，视为信息收集完成；简洁总结后立即进入第2步，不设置确认轮次。
4. 需要用户选择或修改时才停止；用户的明确选择即为确认，不追加重复确认轮次。
5. 上游修改时只重做受影响步骤，保留其他已确认内容。
6. 用户明确说“直接做完”时才连续执行，但最终仍只输出规定内容。
7. 不自动生成视频；用户明确要求后再调用视频生成流程。

内部只使用 `用户提供`、`Skill推断`、`用户确认`、`待补充`、`已失效` 五种状态，不向用户展示。不要把推断自动视为确认；用户回复“确认”“可以”“继续”时，只确认当前展示内容。

## 修改与回退

| 修改内容 | 重新执行 |
|---|---|
| 品牌、产品、卖点、目标人群 | 第1至5步 |
| 题材大类 | 第3至5步 |
| 核心创意 | 第4至5步 |
| 人物、冲突、固定口播、导演时间轴 | 第5步 |
| 最终提示词措辞 | 只重新编译第5步 |

“重新来”保留第1步已确认的产品事实，清空第2至5步。“只改20-25秒”等指令只修改指定段及必要衔接。

## 内容边界

- 只使用用户确认的品牌、产品事实、包装和固定口播。
- 不编造功效、资质、价格、折扣、销量、评价或竞品信息。
- 不使用保证性结果、医疗奇迹或绝对化表达。
- 不仿写具体影视角色或完整情节。
- 产品必须改变故事结果，但不得获得真实卖点之外的能力。

交付前静默检查：五步执行顺序、六段时长、前10秒两个剧情点、每段台词与人数、产品露出节奏、固定口播位置、模块顺序、负面提示词。
