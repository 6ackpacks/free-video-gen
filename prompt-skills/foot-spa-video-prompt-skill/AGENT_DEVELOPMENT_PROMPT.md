# 给开发 Agent 的实现提示词

请基于本目录的 `SKILL.md` 与 `actions/` 下 14 个动作模板，设计并实现一套面向批量图生视频的提示词组装流程及前端模板选择能力。

## 产品流程

1. 用户先固定/上传底图。
2. 图像分析模型识别并保存场景档案：空间类型、固定视角、可行走区域、真实门的位置、透视和可容纳人数。场景档案只描述底图，不增造场景物件。
3. 前端展示 14 个动作模板供用户选择。支持单选，也可提供“从兼容模板中随机选择”。随机模式只在满足底图空间与人物数约束的模板中抽选。
4. 提示词生成模型根据场景档案、动作 ID 与人物/穿搭变量生成最终提示词。
5. 返回提示词、模板 ID、场景档案与人物穿搭选择，便于复现、编辑和记录生成结果。

## 不可违反的业务规则

- 动作模板是固定的动作骨架。生成模型不得改写动作顺序、人物关系、运动方向或结束状态，也不得附加模板没有的动作。
- 模型负责补充人物外貌、体型、发型、穿搭、底图场景描述和句子连接。人物穿搭不能与动作模板冲突。
- 每条提示词都必须带统一视觉质感：老旧摄像头拍摄、轻微模糊、灰蒙蒙一层雾感、低对比、噪点、视频压缩痕迹；不要在提示词里写“CCTV”。
- 每条视频都必须有优雅、舒缓、无歌词的纯音乐。人物可有说话嘴型，但音轨不允许有人声、对白或耳语。
- 女性均为年轻成年女性，漂亮、身材匀称或曲线明显，穿合身修身但得体的衣服；服装可从制服、修身长裙、挂脖裙、细肩带裙、短袖配短裙、T 恤配包臀裙等池子轮换，不能每条都制服。
- 男客人必须成年且穿日常休闲装，如短袖、T 恤、牛仔裤或休闲短裤；不能穿正装。体型采用普通偏胖、微胖、壮实或瘦小等类型，避免高大帅气、纤瘦男模描述。
- 底图是真实空间依据。模板只在底图具有所需门、路线和空间时可选；不得为满足模板而凭空增加门或通道。
- 不把两个动作模板合并成一条视频。一次生成对应一个模板 ID。

## 建议数据结构

每个动作文件应解析或配套暴露以下字段：

```json
{
  "id": "action-09",
  "name": "并肩到门前推门进入",
  "people": ["adult_female_staff", "adult_male_guest"],
  "sceneTags": ["corridor", "visible_door"],
  "endState": "both_inside_room",
  "actionText": "固定动作正文，不允许生成模型改写",
  "selectionEnabled": true
}
```

具体字段可按现有技术栈调整，但必须保留模板 ID、人物数、适用场景、结束状态和锁定动作正文。

## 提示词组装

最终提示词建议由独立字段拼接：

1. 视频时长/画幅（仅使用产品设置的值）。
2. 基于底图分析生成的场景保持描述。
3. 人物外貌与穿搭变量。
4. 锁定的动作正文，作为不可编辑的系统数据插入；不得要求 LLM 重写。
5. 固定老旧摄像头画质段。
6. 固定声音段。

如果采用 LLM 编译，请将动作文本视为原样引用的常量。可在输出后做一致性校验，发现动作顺序或结束状态变化时拒绝结果并重新编译，不能静默修改模板本身。

## 前端建议

- 展示模板编号、名称、简短动作摘要和结束状态。
- 用户选中模板前，展示兼容性状态；不兼容时说明底图缺少对应的真实空间条件。
- 提供“手动选择”和“兼容模板随机抽选”两种方式。
- 提供人物穿搭随机/指定选项；随机需避免同一批任务中的重复组合。
- 显示最终提示词预览，清楚标记底图描述、人物穿搭、锁定动作、画质、声音各部分。
- 记录底图 ID、动作模板 ID、人物/服装组合、最终提示词和生成结果状态，便于批量防重复与追踪。

## 验收要点

- 14 个模板都能被前端发现并选择，模板 ID 稳定。
- 模型生成时只补场景与人物/穿搭，不改动作正文与结束状态。
- 不兼容的模板不会被随机选中。
- 输出始终带画质和音乐规则，且无可听见人声。
- 同一底图可用不同兼容动作与不同穿搭组合生成结果；一条视频只使用一个动作模板。
- 提示词可追溯到所用模板 ID，便于复现。
